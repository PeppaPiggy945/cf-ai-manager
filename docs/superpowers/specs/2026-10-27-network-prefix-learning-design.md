# 当前网络的网段偏好学习

用户目标：优先扫描当前网络中表现好的 Cloudflare 网段，同时持续探索新地址。用户已选择自由推进，比例与算法由实现者决定。

## Approaches

选择：按已完成的真实隧道验证积累网段成绩，70% 偏好/复测、至少 30% 新地址探索；无有效成功证据时回退均衡探索。固定前三名硬切换容易锁定旧路径，仅 TCP 成绩不能说明隧道可用，均不采用。偏好部分在成绩前三的有效网段内按权重分配。

## 行为与约束

- 维持现有 Python/PySide6、256/12/6 默认数量和时间/下载预算，不改生产代理选择或现用启动入口。发布到独立 0.2.6 目录。
- 在服务器实例目录保存 discovery.json，按现有物理网络 identity（网卡 GUID/index、本地 IPv4、网关）、节点指纹、两个探测端点与超时分上下文；保存上限 8 个上下文。它不是城市/运营商或公网出口识别，同一路由器背后的变化可能无法察觉。
- 每段保存最近 30 天、最多 32 个批次摘要，每批贡献上限相同：以完整六次验证的准入比例为主，首次请求和复用连接延迟/波动为辅；7 天半衰期，带平滑先验。一个入口重复六次不是六个独立成功。未准入的段不会因 TCP 快得到偏好。
- 每批先给探索保留 ceil(30% × 总额)，历史/现用种子只占偏好额度；种子不足时用前三个有效好网段的新地址填补，偏好不足转为探索。冷启动均衡轮转各段，段内独立游标，近期地址排除与批内去重照旧。
- 深测也先保留 ceil(30% × 实际深测上限) 的探索候选，优先欠缺深测证据的段、段间分散；其余沿用低延迟/历史候选规则。探索入口 TCP 不通时不能强行深测，记录实际数量。
- TCP 结束后可保存抽样游标；只有验证三轮全部结束、网络复核成功、结果保存后才更新偏好。取消、超时、内核故障或网络变化不记负分。全失败的完整批次最多贡献一批负证据，旧成绩不会一次清零。
- 损坏/未知版本学习记录回退冷启动，其他配置和结果照常可用。仅保存哈希上下文、网段和计数/质量，不保存凭据、订阅正文或探测 URL。
- 进度、结果摘要与测试详情展示偏好/探索/复测实际数、各段额度和扫描前分值，便于核对学习是否影响选取。

## 验收

离线测试证明成功段获得更多地址、全失败段不因 TCP 快受偏爱、30% 新地址和深测探索名额可用、切换上下文不串成绩、过期证据回落、排除/重复/网段耗尽不会无限循环；用隔离 Scanner 集成验证连续批次学习，取消/网络变化不写成绩。全量回归和打包自检后交付，不启动生产扫描。
